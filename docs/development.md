# 开发与验证

## 环境和命令

Node.js 版本由 `.node-version` 维护；pnpm 版本由 `package.json` 的 `packageManager` 维护；依赖版本由 `package.json` 和 `pnpm-lock.yaml` 维护。

| 命令                                | 用途                        |
| ----------------------------------- | --------------------------- |
| `pnpm dev`                          | 启动本地开发服务器          |
| `pnpm typecheck`                    | TypeScript 严格类型检查     |
| `pnpm lint` / `pnpm lint:fix`       | Oxlint 检查 / 自动修复      |
| `pnpm format` / `pnpm format:check` | Oxfmt 格式化 / 只读格式检查 |
| `pnpm test` / `pnpm test:watch`     | Vitest 单次执行 / 监听      |
| `pnpm build` / `pnpm preview`       | 构建静态站点 / 预览构建结果 |
| `pnpm check`                        | 执行全部必要检查和构建      |

CI 通过 `pnpm install --frozen-lockfile` 安装，再执行 `pnpm check`。格式化修复仅在本地执行。

## Cloudflare Workers 部署

项目通过根目录的 `wrangler.jsonc` 配置 Workers Static Assets，直接发布 Vite 生成的静态文件。Worker 名称、兼容日期和资源目录以该文件为准。

在 Cloudflare 网页连接仓库后，生产分支选择 `main`，根目录保持仓库根目录，构建命令填写 `pnpm build`，部署命令填写 `npx wrangler deploy`。Node.js 使用 `.node-version` 指定的版本，构建环境变量 `PNPM_VERSION` 与 `package.json` 的 `packageManager` 保持一致。

非生产分支使用 `npx wrangler preview` 创建预览。配置中的空 `previews` 块是该命令的必要条件；静态资源目录和兼容日期仍由顶层配置提供。配置规则见 [Cloudflare Previews](https://developers.cloudflare.com/workers/previews/configuration/#wrangler-configuration-file)。

已有配置会让 Wrangler 跳过框架自动配置，避免在部署时向项目安装 Vite 适配器及其依赖。项目无需安装 Wrangler 开发依赖，发布工具由 `npx` 按需获取。先运行 `pnpm build`，再运行 `npx wrangler deploy --dry-run` 可在不发布到云端的情况下校验部署配置。

自定义域名确定后，可在 `wrangler.jsonc` 的 `routes` 中添加 `custom_domain: true` 的域名条目；域名所在 Zone 需已在 Cloudflare 激活。配置方式见 [Cloudflare Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)。

## 实现导航

- `src/main.ts`：页面交互、可见性暂停、错误状态和生命周期。
- `src/simulation/flush-cycle.ts`：独立于浏览器的冲水时间轴；水箱与便池的状态来自同一时间采样。
- `src/constants.ts`：周期、静止水位、便池截面、阶段名称、力度档位和水箱洁厕块的染色配置。
- `src/scene/toilet-model.ts`、`geometry.ts`、`bowl-profile.ts`：马桶曲面与共享截面定义。
- `src/scene/create-scene.ts`：相机、光照、离屏背景、盖子开合和资源释放。
- `src/scene/water-simulation.ts`：GPU 高度场与泡沫平流，固定时间步的双缓冲更新。
- `src/scene/shaders/`：主体水面与贴壁水层。
- `src/audio.ts`：用户交互后启用的 Web Audio 实录播放、声道包络、静音与暂停恢复。
- `src/sound-preference.ts`：仅在用户选择记住时保存声音开关；有效记录同时表示不再显示首次声音询问。
- `public/audio/`：随应用提供的冲水与补水录音；来源和编辑记录见其中的 `CREDITS.md`。

`index.html` 与 `src/style.css` 中的 `.scene-frame` 定义模型的可用区域。场景初始化时接收该元素，尺寸变化时根据它相对画布的实际边界计算正交相机，让模型与控件共用布局中线。调整桌面或窄屏排列时只修改 CSS 区域，不在相机中重复维护断点、页边距或控件高度。

水面与陶瓷必须共同使用截面定义。水位由状态机更新，波纹与光照不能改变状态机的水量。离屏背景包含颜色和深度，供水面和贴壁水流折射取样，在初始化、尺寸变化及盖子开合时更新；盖子静止后复用。捕获背景时隐藏两层水，避免采样反馈。两层水共用 `water-optics.glsl` 的吸收函数。GLSL 使用 Vite 的 `?raw` 导入。

`rim-flow.glsl` 是贴壁水、入水过渡和模拟入口的共同流束定义，宽度、摆动和纹理相位都使用高度场输出的同一时钟。入口不再另行生成脉冲条纹。水深在接触线归零时，进水薄膜仍有厚度：主体水面沿用薄膜光程、折射和细小高光，向内再过渡到池水深度，不能仅以水深把染色清零。改变任一水层时，应一起检查这三个使用位置，避免颜色或纹理在移动水线处断开。

渲染器启用 MSAA，像素倍率通常为 1.5–2，并以 600 万像素限制大窗口显存占用。折射背景与实际绘图缓冲区尺寸一致，使用四重采样，不再以较低的 CSS 像素分辨率放大池底。程序化细节按 `fwidth` 过滤，水面高光按法线导数展宽；仅提高画布分辨率不能解决着色器内部的闪烁。

水面模拟使用 192 × 192 半浮点纹理，RGBA 分别存储位移、垂直速度、泡沫和旋流迹线强度；通过双缓冲避免同一帧读写同一张纹理。迹线调节微小波峰和吸收光程，不作为不透明色块混入画面。固定步长为 1/90 秒，每帧最多推进六步，避免低帧率时补算失控。网格尺寸、差分间距和时间步必须一起校验；调整参数后需要在浏览器检查强劲档、结束后的衰减和控制台。模拟用纹理不参与色调映射，水面材质在最终输出时统一处理颜色。

业务时间轴使用前台帧之间完整的经过时间，不能截断长帧，否则持续播放的录音会领先画面。接受新的冲水请求时，以实际点击时刻重设计时基准，不能把点击前的停顿计入新循环；被拒绝的重复请求不能重置计时。同一帧的 RAF 时间戳若早于点击时刻，应保留较新的基准，避免负时间步。数值积分的步数上限仅约束 GPU 模拟；切后台仍暂停时间轴，并在返回时重置帧时间基准。

所有冲水入口与按钮状态共同使用 `FlushCycle.canStart`。Boost 的提前解锁时间由 `FLUSH_END_TIME` 与阶段转换共享；模式切换要立即更新界面，即使当前阶段没有变化。提前重启时将当前水箱和便池水位作为新一轮初值，补足尚未蓄满的水量，避免把水位重置为满水位。

创建环境贴图和水面纹理前，检查 `EXT_color_buffer_float` 或 `EXT_color_buffer_half_float`。两者均不可用时释放渲染器并拒绝初始化，由入口统一显示加载失败、禁用冲水；不能只依赖着色器编译异常捕获。

场景异步初始化完成时，需要再次检查上下文失败与页面销毁状态；失效后才返回的场景应立即释放，不能隐藏错误或重新启用控件。已销毁页面的初始化失败也不能覆盖新页面状态。

## 验证范围

Vitest 覆盖重复触发、阶段转换、水量范围、循环复位、不同帧率、异常时间步、力度锁定及三档差异、补水与冲水声音包络、默认静音及声音记忆的缺失、有效、无效和存储失败情况。入口回归还覆盖点击前后的长帧、早于点击的帧时间戳、后台暂停恢复、初始化失败、上下文丢失或页面销毁后的异步完成，以及缺少浮点颜色附件扩展时的拒绝初始化和资源释放。类型检查与单元测试不能代替 WebGL、听感和视觉验收。

浏览器验收应检查：

1. 画面正常加载，没有 Shader 编译错误；可通过界面、空格和水箱按钮冲水。
2. 水位先略升、随后降低，再自动恢复；贴壁水流、旋流和泡沫随阶段变化。
3. 默认冲水和补水期间重复触发不会叠加，完成后按钮恢复可用；开启 Boost 后仅在冲刷结束后提前解锁。
4. 静音即时生效；切至后台时暂停动画并静音，回来后继续。
5. 桌面和窄屏布局没有遮挡操作区、裁切模型或横向溢出；覆盖 1920/2560 像素宽屏、短窗口和 800 像素断点两侧，确认马桶与冲水按钮中线一致、模型下沿和控件有间隔，且水箱按钮仍能点击。
6. 三档力度的座圈下沿喷流、旋流和泡沫有区别；不可再次冲水时锁定力度，可以再次冲水时恢复选择。
7. 水箱洁厕块的四种选项可以实时切换，池底依然可见；水柱从座圈下沿出现时就带有所选颜色，与旋流和积水的色调一致。重点检查强劲档入水后的流带不能被白色泡沫覆盖，三种染色都应保留。选择无添加时恢复清水，不能残留统一的蓝绿色喷流。
8. 音频文件正常加载与解码；补水在冲水尾段接入，声音符合合盖水箱的低闷、轻柔特征，明显弱于冲刷声，无刺耳的高频嘶声；持续进水后保留轻微关阀收尾，蓄满后安静，无原有电子低鸣。三档补水音色一致，椭圆马桶盖开合不改变水箱声音，中途静音和恢复不重播开头。
9. 能区分宽坐面的座圈、下方陶瓷边沿和向后掀起的椭圆盖；开合没有穿过座圈的明显画面错误，盖上遮住水面、掀开重新露出，水箱按钮不被挡住。
10. 旋转细带、波纹、折射与泡沫一起运动，三档强弱有区别；条纹应有粗细、断续和汇聚变化，结束后水面逐渐平静。
11. 检查座圈内外轮廓、水下喉口和冲水高光的边缘；桌面与窄屏均应保持平滑，不能出现明显的像素台阶或高频闪烁。水柱接触水面时不能出现整圈白边，染色流带中仍应看得见池底深浅与折射变化。接缝回归检查应覆盖约 2.6 秒的强进水、约 5 秒的低水位和后续补水：沿单股水柱观察，颜色、宽度与运动节奏应连续进入水面，不能在水线突然变白或横向错开。
12. 没有声音记忆时，首次弹窗默认不勾选“下次不再提示”，焦点在“保持静音”，背景操作与空格冲水被阻止。分别验证两种选择、Escape、未记忆后刷新、记忆开启或静音后刷新，以及右上角切换后保存状态；检查窄屏弹窗可完整操作。
13. 在实验副本中注入 1 秒前台主线程停顿，恢复绘制后音画应继续对齐；模拟两个浮点颜色附件扩展均不可用时，应显示加载失败并禁用冲水，不能以黑色水面进入就绪状态。
14. Boost 默认关闭；在补水阶段切换开关时，主按钮和力度选择立即同步。开启后可通过页面、空格或水箱按钮再次冲水；连续触发不能中断正在进行的冲刷，提前重启不能让水位突然跳高，停止点击后应恢复蓄满。检查窄屏与桌面下开关和状态文字不重叠。

实际移动设备的 GPU 性能与声音观感需要实机验证；桌面浏览器的窄屏模拟仅验证布局。需求范围见[冲水体验](specs/flush-experience.md)。
